# 本地使用与开发

## 安装与目录

Node.js >=22.19.0。仓库根目录运行 `npm.cmd run setup` 后执行 `npm.cmd run build`。
固定在 `E:/project/NovelPilot` 运行 `npm.cmd run dev`，或运行 `node cli/dist/main.js`。
空项目直接进入未命名共创；已有小说时用菜单选择继续或新建共创，不再出现强制填写书名的表单。
也可运行 `npm.cmd run dev -- --book 灯塔` 打开指定书籍，或使用你已经想好的名字。

程序通过操作系统锁独占本书；锁文件存在不代表进程仍在运行，不要删除正在使用的锁文件。
换书时退出 TUI，在同一项目目录重新启动并选择另一作品。单个未命名草稿可直接恢复；多个草稿会出现在列表中。已开始的作品读取保存状态并尝试恢复工作；未接纳的外部修改会阻止续写。

## 讨论和写作

1. 点击底部「设置」打开单页表单。↑↓ / Tab 选择字段，←→ 切换范围、角色和选项，Enter 原位编辑文本，Ctrl+S 或「保存当前配置」统一保存；Esc 取消。容量支持 `128K` / `1M`。可以给规划、写作、评审分别配置覆盖值，讨论和意见判断使用默认值。
2. 直接输入人物、世界观、设定或修改想法，右侧/下方草稿区域显示当前完整要求。
3. 草稿非空后点击「开始创作」或按 Ctrl+S。没有确定书名时会根据讨论内容提供候选，默认选项直接采用推荐名；也可自行填写或返回讨论。已有明确书名则沿用。模型表示准备好了，不会自动开始。
4. 自动创作中可以直接输入意见；长期规则、后续规划和已有章节返工分别处理，控制动作在任务边界执行。
5. 底部主操作随状态显示「暂停」或「继续写作」。只要求修改已写内容时默认改完暂停，明确“改完继续”才继续推进。

角色工具的结构检查不能证明文学质量。自然语言意见有歧义时会要求澄清，不自动扩大改稿范围。

## 常用操作

点击「操作 F2」或按 F2 打开可搜索菜单，输入中文、命令名或描述筛选；菜单只显示当前阶段适用的操作。
共创时左侧对话和输入、右侧完整草稿，Tab 切换焦点，箭头/翻页键滚动当前栏。开始写作后显示三栏：左侧概览/角色/本次用量，中间事件流/实时内容，右侧章节/人物/设定。较窄窗口自动收拢。
下面的命令是可选快捷方式，不是必须记住的操作步骤。

| 操作 | 命令 |
| --- | --- |
| 阶段讨论后续方向 | `/cocreate` 或 `/plan` |
| 应用阶段讨论完整草稿 | `/apply` |
| 放弃阶段讨论，保持暂停 | `/cancel` |
| 检查外部正文修改，不调用模型 | `/sync --check` |
| 同步外部修改的事实和影响 | `/sync` |
| 导出当前成稿 | `/export txt` 或 `/export epub` |
| 导出部分章节 | `/export epub 1-3` |
| 明确覆盖已有导出文件 | `/export txt --overwrite` |
| 只读诊断 | `/diag` |
| 导出脱敏诊断 | `/diag --export` |
| 模型设置 | `/settings` |
| 帮助 / 退出 | `/help` / `/quit` |

导出保存在书目录的 `exports/novel.txt` 或 `exports/novel.epub`。未完成章节列为跳过；已经完成但正文缺失则报错。
导出会先等待当前运行停稳，之后可用 `/resume` 继续。
阶段共创需要已开始且未完本的书；取消不应用草稿。已完本只支持明确章节的修订，不提供新增剧情入口。

输入：Enter 发送，Shift+Enter 或 Alt+Enter 换行。PgUp/PgDn 滚动，Ctrl+End 回到底部；共创时 Tab 切栏，F2 搜索操作。输入 `/` 可补全当前阶段的快捷命令。
Ctrl+C 在运行时暂停，其他状态退出；配置弹窗中取消输入。凭证输入使用遮罩，不写入聊天历史。

## 文件与恢复

未命名阶段使用程序管理的 `books/.drafts/<编号>/`，用户无需起临时名字。有效共创草稿和用户意见会保存；重启可继续。命名后在保持作品身份锁的情况下整理到 `books/<书名>/`，若同名目录已存在则增加目录后缀，不合并或覆盖旧书。
受管作品的锁位于 `books/.locks/`，命名前后使用同一身份；命名移动与启动意图可恢复。不要手工移动正在运行的作品或删除锁文件。

- `chapters/NN.md`：可以用外部编辑器修改的正文。
- `drafts/`：当前章工作草稿。
- `meta/chapter_records/`：完整已接纳正文、哈希、版本和章节事实。
- `meta/progress.json`、`meta/planning.json`：创作进度、计划及内部任务状态。
- `meta/pending_commit.json`、`meta/pending_revision.json`：中断时的固定内容和恢复阶段。
- `meta/checkpoints.jsonl`：持久步骤证据。
- `meta/interventions.json`、`meta/control.json`：用户意见及运行意图。
- `meta/discussion.json`：共创草稿和用户意见；`meta/start-intent.json`：用户已确认的命名与启动意图。
- `summaries/`、`meta/story_state.json`：从接纳记录得到的故事记忆。
- `meta/runs.jsonl`、`meta/usage.jsonl`：运行和用量记录。

外部改稿后先检查、再同步。同步保持用户正文，模型提取事实；分析后又修改正文会拒绝过期分析。
损坏记录或无法判定的部分同步冲突会保留证据并报错，不静默当成空书。
可在项目目录运行 `node cli/dist/main.js --diag --book 灯塔` 做只读诊断。

## 开发验证与评测

`npm.cmd run check` 执行类型检查、测试和构建。
`npm.cmd run smoke:pack` 在临时目录安装本地包并验证资源与书目录绑定，不发布软件。

```powershell
npm.cmd run eval
npm.cmd run eval -- --repeat 3
npm.cmd run eval -- --real
```

默认案例使用确定性工具驱动，不调用真实模型。`--real` 默认使用全局模型配置；加 `--book 灯塔` 可使用指定书籍的角色模型配置，评测产物仍在独立目录，会调用付费模型。
评测创建隔离书目录并输出报告，包含成功和失败、当前代码/依赖指纹、案例和评分版本；模型内部评分独立列出。
源码、Prompt、工具或策略修改后重新运行同一案例即可对照。未知费用为 null，不等于免费。
